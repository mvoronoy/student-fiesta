1. Які ще колонки крім zipcode, latitude, longitude можна надрукувати в цій реалізації?
У реалізації через словник під час читання рядка доступні всі колонки файлу Barcelona1.csv, але спосіб їх виведення залежить від логіки групування:
1. Список значень усередині групи можна додатково виводити список усіх id або нейм для кожного zipcode, також застосовувати агрегатні функції.
2. Одиночне значення без агрегації - можна вивести лише ті колонки, які однакові для всього поштового індексу (country та smart_location). Колонки id та name унікальні для кожного рядка, тому вивести їх одним значенням на весь zipcode неможливо.

2. Чи можна пришвидшити ваш алгоритм?
Так, алгоритм можна пришвидшити кількома способами:
1. Використання хеш-таблиць. Що дає лінійну складність O(N) для GROUP BY та O(N + M) для JOIN/UNION/NOT-IN замість повільного перебору вкладеними циклами O(N * M).
2. Робота з числами замість рядків. Координати можна переводити у float або цілі числа (помножені на 10^6) - числа займають менше пам'яті та швидше порівнюються й хешуються.
3. Потокова обробка. Для JOIN та NOT-IN можна завантажити в пам'ять лише ключі меншого файлу (Barcelona2.csv), а більший файл (Barcelona1.csv) читати по одному рядку без збереження всього списку в оперативній пам'яті.
4. Перехід на компільовану мову (наприклад, C++ із std::unordered_map) або паралельна обробка файлу частинами на кількох ядрах процесора (підхід MapReduce).
